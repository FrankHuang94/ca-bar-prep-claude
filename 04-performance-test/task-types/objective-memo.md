# Objective (predictive) memorandum

> **How often this appears on California PTs:** to be filled in from [past-pt-index.csv](../past-pt-index.csv) in Phase 3. No frequency is stated until then.

## Purpose
- An internal memo to a supervising lawyer. It **predicts** how the law in the Library applies to the facts in the File, so that the supervisor can decide what to do.
- The reader wants an honest assessment, **weaknesses included**, not advocacy.
- Typical memo verbs: "analyze", "evaluate", "assess the likelihood", "advise me whether".

## Format template

Use only the sections the task memo asks for. If it specifies a format, follow it over this template.

```text
MEMORANDUM

TO:      [Supervising attorney, as named in the task memo]
FROM:    Applicant
DATE:    [date given in the File, or as instructed]
RE:      [Client / matter]: [the question in a few words]

[QUESTION(S) PRESENTED]   <- only if requested
1. Under [Columbia law / statute], does/can [client] [legal question] when [key facts]?

[BRIEF ANSWER(S)]          <- only if requested
1. Probably yes/no. [One or two sentences: the rule and the deciding facts.]

[STATEMENT OF FACTS]       <- only if requested; many task memos say NOT to include one

DISCUSSION
I.  [Issue 1 as a descriptive heading, e.g., "Whether the Covenant Not to Compete Is Enforceable"]
    A. [Element / factor 1]
       Rule (Library authority) -> how courts applied it (case facts) -> our facts
       -> counter-arguments and weaknesses -> mini-conclusion
    B. [Element / factor 2] ...
    Conclusion on Issue 1
II. [Issue 2] ...

CONCLUSION
[Overall prediction; key risks; facts still needed; recommended next steps if asked]
```

## Tone
- **Neutral and predictive:** "a court will likely find", "the stronger argument is", "this factor weighs against us".
- Present **both sides** of every close issue, then predict.
- Name your client's weaknesses plainly. That is the point of an objective memo.
- Professional, but not ornate. Short sentences.

## Common mistakes
| Mistake | Fix |
|---|---|
| Advocating ("clearly", "plainly", ignoring bad facts) | Rewrite as a prediction and add the counter-argument. |
| Summarizing each Library case in turn | Organize by element; use each case where it bears on that element. |
| A statement of facts the memo said not to include | Re-read the "do not" list (method §4). |
| Descriptive headings that hide the answer, e.g., "Analysis" | Use issue headings ("Whether..."). You may add the conclusion ("The Covenant Is Likely Unenforceable Because..."). |
| No conclusion on a close issue | Always predict ("more likely than not"). |
| Ignoring missing facts | Say what further facts would change the prediction, if the task allows. |

## Checklist
- [ ] Heading block (TO/FROM/DATE/RE), with no real name.
- [ ] Only the sections requested, in the requested order.
- [ ] One Discussion heading per issue the memo assigns.
- [ ] Every rule cites a Library authority by name.
- [ ] Analogies and distinctions use specific case facts.
- [ ] Bad facts and counter-arguments are addressed.
- [ ] A clear prediction for each issue and overall.
- [ ] Missing facts or next steps flagged, if asked.
